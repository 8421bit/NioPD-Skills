# Design Sprint Skill

This skill applies the Google Ventures Design Sprint methodology for rapid validation in 5 days.

## Theoretical Foundation

### Origin
The Design Sprint was developed at **Google Ventures** by **Jake Knapp** and documented in "Sprint: How to Solve Big Problems and Test New Ideas in Just Five Days" (2016).

### The 5-Day Structure

| Day | Focus | Outcome |
|-----|-------|---------|
| **Monday** | Map | Problem defined, target chosen |
| **Tuesday** | Sketch | Solutions on paper |
| **Wednesday** | Decide | Best ideas selected |
| **Thursday** | Prototype | Realistic facade built |
| **Friday** | Test | User feedback collected |

### Key Principles
- Time-boxed decisions
- Real user validation
- Team alignment
- Bias toward action
- Learning over launching

### When to Use
- High-stakes decisions
- New product initiatives
- Major feature changes
- Entering new markets
- Breaking analysis paralysis

## Instructions

### Monday: Map
1. Set long-term goal
2. List sprint questions
3. Create map of user journey
4. Choose target area

### Tuesday: Sketch
1. Lightning demos (inspiring examples)
2. Four-step sketching:
   - Notes
   - Ideas
   - Crazy 8s
   - Solution sketch

### Wednesday: Decide
1. Art museum (display sketches)
2. Heat map voting
3. Speed critique
4. Straw poll + Supervote
5. Create storyboard

### Thursday: Prototype
1. Assign roles (Makers, Stitcher, Writer, Asset Collector, Interviewer)
2. Build realistic prototype
3. Trial run

### Friday: Test
1. Conduct 5 interviews
2. Observe together
3. Identify patterns
4. Document learnings
